Code blocks — two candidate treatments

Source change: a function signature's parameter renamed, one line added. Same underlying edit, two different diff granularities — pick whichever reads better for code specifically.

A — Line-level (matches DiffView.tsx)
Rendered · example.md
function connect(  host: string,  hostname: string,  port: number,  timeoutMs = 5000,): Promise<Connection> {  ...}
Whole changed lines get a red/green background, exactly like the raw diff view and like DiffView.tsx already does. Familiar to anyone who's read a code diff before; no new mechanism to build (line-level diff already exists in this codebase for the raw view).
B — Word-level (matches prose)
Rendered · example.md
function connect(  host: string,hostname: string,  port: number,  timeoutMs = 5000,): Promise<Connection> {  ...}
Only the changed token (host → hostname) is highlighted within the line, same visual language as prose. Reads oddly on renames/refactors where most of a line's tokens are unrelated to each other structurally (unlike prose words, which read as a sentence) — e.g. here it's fine, but a line with multiple unrelated token changes could look noisy with several small spans instead of one clean line-level bar.
My recommendation: A (line-level), matching the raw diff view's existing convention and avoiding a second bespoke diff mechanism for code specifically — word-level tokenization is tuned for natural-language text (the LCS word-diff already built for prose), and code's token boundaries (operators, punctuation, identifiers) don't map cleanly onto that. But this is exactly the kind of call better made by looking at both side by side, which is why both are mocked out above.
